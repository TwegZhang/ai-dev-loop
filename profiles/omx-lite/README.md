# OMX-Lite Profile

[&#31616;&#20307;&#20013;&#25991;](README.zh-CN.md)

OMX-Lite applies AI Dev Loop's Human-controlled iteration boundary to OMX execution. It is a sibling of the [Native Codex Profile](../native-codex/README.md), not a separate methodology or an OMX fork. OMX Default is the upstream baseline/reference.

Keep **Project → Iteration → Lane → Task → Inner Loop** and **Reality → Memory → Human Judgment → Contract**. Human owns direction, architecture, iteration boundaries, and release decisions. OMX coordinates bounded execution inside the approved Iteration Contract.

## Use existing assets

- [Operating policy](../../policy/OMX-LITE-POLICY.md): hard dependencies, outcome lanes, safe deferral, escalation, and STOP.
- [Iteration skill](../../skills/iteration/SKILL.md): start, review, memory, status, and close workflows.
- [Iteration Contract](../../templates/ITERATION-TEMPLATE.md), [Iteration Result](../../templates/ITERATION-RESULT-TEMPLATE.md), and [Deferred Engineering Memory](../../templates/DEFERRED-LEDGER-TEMPLATE.md): canonical artifacts.
- [Project setup](../../docs/05-Project-Setup.md) and [OMX integration](../../integrations/OMX.md): installation and execution guidance.
- [Profile selector](../../docs/06-Choosing-an-Execution-Profile.md): compare six dimensions and exceptions before adopting coordination overhead.

Use the lightest supported OMX execution surface that fits the current iteration. Runtime availability and ownership remain governed by the installed OMX workflow; this directory does not add runtime state or duplicate the policy, skills, or templates.

Close with completed/incomplete outcomes, evidence, TD, DV, EG, KR, engineering learning, and Human decisions, then **STOP**. Reconcile memory before handing control back. The next iteration requires Human judgment from refreshed Reality + Memory. Remembered ≠ Scheduled Now; Iteration Complete ≠ Fully Verified ≠ Release Ready. Generated project artifacts are English; Human-facing discussion may use the preferred language.
