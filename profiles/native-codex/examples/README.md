# Native Codex worked example

This fictional example shows a desktop/web settings feature, from Human architecture judgment to a Phase result. Paths, commands, and results describe an illustrative target project; they are not files or checks implemented by this documentation repository. All evidence below is illustrative, not a claim that tests ran here.

Read in order:

1. [Execution Plan](EXECUTION-PLAN.md): current Phase with an embedded Iteration Contract.
2. [Runtime contract Goal](goals/goal-runtime-contract.md): establish and test the shared boundary.
3. [Web integration Goal](goals/goal-web-integration.md): begin once the runtime contract is integrated.
4. [Phase 01 result](phase-01-result.md): evidence, memory, Human decisions, and STOP.

The example deliberately has a hard dependency, so its two implementation goals run serially. A read-only review can run alongside either goal. Independent CLI `/goal` sessions are an optional Human-started alternative, not a requirement or an automatically scheduled fleet.

Phase maps to a Human-controlled Iteration; each Goal here is an outcome Lane. A smaller Goal could instead be a bounded Task. Neither changes Project → Iteration → Lane → Task → Inner Loop or replaces Reality → Memory → Human Judgment → Contract.
